# 各阶段提示词模板

> 源自实战视频演示，已泛化为模板；`{ }` 为占位符。均可直接复制给 AI 编程工具（Codex / Claude Code / Cursor 等）使用。
> 使用要点：**一次只推进一个阶段**；AI 给建议后，由人决策、砍范围、确认文档。

---

## C-1 产品设计 · MVP 讨论（阶段二）

```
我想做一个{产品类型}，打算先从 MVP 版本开始。
你觉得这一个版本做哪些功能比较合适呢？
```

**用法**：拿到 AI 的功能清单后，**逐项砍范围**——每个功能问"没有它，主流程还能跑通吗？"，把砍掉的放进"不做清单"。示例：EPUB 解析复杂 → 首版只支持 TXT；三种主题 → 只留明亮主题；书签 → 延后。

---

## C-2 产品设计 · 整理文档（阶段二）

```
请把刚才讨论的内容整理成一份产品设计文档，不用太详细，
梳理整体方向和主要功能即可。
```

**用法**：配合 `assets/product-design-template.md` 使用；产出存为 `docs/product-design.md`，由用户确认后才进入下一阶段。

---

## C-3 产品设计 · 制作 Demo（可选，阶段二）

```
帮我做一个 Demo，不用实现真实的后端功能，数据模拟一下就行。
我主要是想看看整体界面和操作流程是否合理。
```

**用法**：判断标准是**后端实现成本**——后端重（文件处理、搜索、模型调用等）先做 Demo；后端轻（如仅导入本地文本）直接做完整 MVP。

---

## C-4 技术设计 · 方案讨论（阶段三）

```
在这个目录下面有一份产品设计文件，请你读一遍这个产品设计文件，
然后告诉我用什么技术栈设计这个产品比较合适。
不用给出过于详细的设计，我们就先探讨一下。
我听说{候选技术}还可以，你怎么看呢？
```

**用法**：建议**新开会话**执行此提示词（隔离旧上下文）；主动追问 AI："这个方案的缺点是什么？有什么备选？"——决策需要取舍信息。

---

## C-5 技术设计 · 写方案文档（阶段三）

```
请把刚才讨论的技术方案整理成一份文档，放在 docs 文件夹中。
```

**用法**：配合 `assets/tech-design-template.md` 使用；只锁大方向，不要求细节完备。

---

## C-6 产品实现 · 实现产品（阶段四）

```
这个目录下面有两个文件，一个是产品设计，一个是对应的技术方案，
请你读一下这些文件，然后根据里面的要求实现这个产品。
```

**用法**：开工前确认 AI 已具备自测能力（运行、页面检查、测试）；实现完成后要求 AI 报告自测结果，随后安排人工冒烟测试。

---

## C-7 人工验证 · 反馈报错（阶段四 / 五）

```
{描述操作步骤}之后，直接显示了一个报错：{报错原文}。
```

**示例**："打开之后，直接显示了一个报错：操作失败，请稍后重试。"

**用法要点**：**原样描述现场**——含操作步骤与报错原文，不做二次转述、不加主观推测，让 AI 拿到第一手信息。修复后必须复验。

**完整版模板**：`assets/issue-report-template.md`（含环境信息 / 复现频率 / 期望 vs 实际 / 边界说明）。

---

## 通用技巧

| 技巧 | 说明 |
|---|---|
| 新会话隔离 | 技术设计、产品实现各自新开会话；重要共识写进文档，不依赖对话记忆 |
| 术语统一 | 讨论前先确认核心名词的定义与范围，避免歧义被 AI 放大 |
| 指向文件 | 指令中明确文档路径（"这个目录下有两份文件"），让 AI 从文档取上下文 |
| 阶段收口 | 每个阶段产出交付物后暂停，核对 DoD 再推进，不要一口气跑到黑 |
| 决策留给人 | AI 只出建议；砍功能、选技术栈、验收结论由人确认 |
