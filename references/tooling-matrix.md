# 验证工具适配矩阵（能力 × 工具）

> **用途**：落地阶段一 DoD 第 3 条——"AI 工具可自测"。
> **维护约定**：以各工具官方文档为准，版本迭代可能变化；本表记录当前可行做法（2026-10）。

## 一、能力齐备三问（任何工具通用自检）

1. **AI 能自己把项目跑起来吗？**——能执行启动 / 构建 / 测试命令；
2. **AI 能自己看到运行结果 / 页面吗？**——能读取输出、截图或检查页面；
3. **失败时 AI 能看到原始报错吗？**——能拿到完整 stderr / 日志。

三问全部为"能"→ 满足阶段一 DoD；任一项为"不能"→ 先补齐配置，再进入产品实现。

## 二、能力 × 工具矩阵

| 工具 | 执行命令 | 观察界面 | 读取日志 | 写验证结论 | 配置要点 |
|---|---|---|---|---|---|
| **Codex** | ✓ 内置 | ✓ Computer Use + Chrome 插件 | ✓ | ✓ | 安装 Computer Use / Chrome 插件（视频演示组合） |
| **Claude Code** | ✓ Bash / 文件工具 | △ 需浏览器 MCP（如 Playwright） | ✓ | ✓ | 配置浏览器类 MCP server 后具备截图 / 读页能力 |
| **Cursor** | ✓ 终端 | △ 内置浏览器预览（视版本） | ✓ | ✓ | 使用 Agent 模式的终端与浏览器预览 |
| **WorkBuddy** | ✓ 命令行 | △ 需启用浏览器控制 + 扩展 | ✓ | ✓ | 设置 → Agent → 浏览器控制 |
| **Gemini CLI** | ✓ shell 工具 | △ 需 MCP 浏览器工具 | ✓ | ✓ | 按官方文档配置 MCP |
| **DeepSeek Harness** | ✓（dsh CLI） | △ 视插件能力 | ✓ | ✓ | 参见 DSH 插件文档 |

> 图例：✓ 开箱或简单配置可用；△ 需额外插件 / MCP / 开关；未列出的工具按"能力齐备三问"自查。

## 三、最小配置示例（Codex）

1. 安装插件：**Computer Use**（操作电脑）、**Chrome**（查看浏览器页面）；
2. 验证：让 AI 启动项目并截图确认页面正常渲染；
3. 失败路径：故意引入一个报错，确认 AI 能读到完整 stderr 并自行修复。

## 四、与其他阶段的关系

- **阶段一 DoD**：用本矩阵确认"可自检"护栏就位；
- **阶段四**：AI 自测依赖上述能力，缺失会导致人沦为人工测试员；
- **阶段五**：人工验收不可被上述能力替代（AI 自测 ≠ 无 Bug）。
